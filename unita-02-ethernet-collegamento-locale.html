01

Problema originario

Conoscere la destinazione IP non muove ancora un segnale sul cavo

Internet Protocol identifica la destinazione logica attraverso reti differenti. Per trasmettere sul collegamento corrente serve però un formato locale, un destinatario raggiungibile su quel collegamento e un controllo degli errori di trasmissione.

MAC

A chi sul link?

L'indirizzo Media Access Control (MAC) destinazione identifica la scheda o l'interfaccia del prossimo dispositivo nel dominio Layer 2.

TYPE

Che cosa trasporta?

Il campo Length/Type permette al ricevente di interpretare il payload: per esempio IPv4, IPv6, Address Resolution Protocol o MPLS.

FCS

È arrivata integra?

La Frame Check Sequence (FCS) consente di rilevare corruzioni accidentali della trama sul collegamento. Non effettua ritrasmissioni end-to-end.

Il destinatario Ethernet non è necessariamente l'host IP finale.
Se la destinazione IP è remota, la trama viene indirizzata al Media Access Control del gateway o next hop locale. Address Resolution Protocol (ARP) risolve, in IPv4, l'indirizzo IP del prossimo hop nel relativo indirizzo MAC.
Contesto storico. Ethernet nacque per condividere un mezzo fra più stazioni. Le reti moderne usano quasi sempre collegamenti commutati full-duplex: Carrier Sense Multiple Access with Collision Detection (CSMA/CD) rimane importante storicamente, ma non governa una normale porta switch full-duplex.

Bridge e dominio Layer 2

Lo switch impara dalla sorgente e inoltra verso la destinazione

Un bridge Ethernet mantiene una Forwarding Database (FDB), spesso chiamata tabella Media Access Control (MAC). L'associazione essenziale è indirizzo MAC + Virtual Local Area Network (VLAN) → porta. Non usa la porta Transmission Control Protocol (TCP) o il Sequence Number per il normale switching.

?

Unknown unicast

Se la destinazione è sconosciuta, la trama viene replicata sulle porte ammesse della stessa VLAN, esclusa quella d'ingresso.

DST

Destination (DST) · Known unicast

Quando la destinazione è nota, lo switch inoltra soltanto sulla porta associata, salvo condizioni particolari.

Attraversando uno switch, gli indirizzi MAC normalmente non cambiano.
Lo switch inoltra la stessa comunicazione Layer 2. Può trattare o modificare il tag VLAN in base al tipo di porta e ogni trasmissione sul link possiede la propria Frame Check Sequence. Uno switch store-and-forward verifica la FCS prima di inoltrare; uno switch cut-through può iniziare l'inoltro prima di aver ricevuto la FCS. Un router, invece, termina la trama.
05

Separazione logica sullo stesso apparato

IEEE 802.1Q aggiunge contesto alla trama

Una Virtual Local Area Network (VLAN) crea un dominio Layer 2 logico. Su un trunk, il tag IEEE 802.1Q indica a quale VLAN appartiene la trama; su una tipica porta access, il dispositivo finale trasmette e riceve trame senza tag.

Legenda: LAN = Local Area Network; VLAN = Virtual Local Area Network; MPLS = Multiprotocol Label Switching; MAC = Media Access Control; IP = Internet Protocol; FCS = Frame Check Sequence; TPID = Tag Protocol Identifier; TCI = Tag Control Information; PCP = Priority Code Point; DEI = Drop Eligible Indicator; VID = VLAN Identifier.

TPID

Tag Protocol Identifier (TPID)

Il valore 0x8100 identifica normalmente un Customer Virtual Local Area Network Tag (Customer VLAN Tag). Il ricevente sa che i successivi 16 bit sono Tag Control Information (TCI).

TCI

Tag Control Information (TCI)

Priority Code Point (PCP): 3 bit. Drop Eligible Indicator (DEI): 1 bit. VLAN Identifier (VID): 12 bit; i valori operativi ordinari sono 1–4.094.

S+C

Service Tag + Customer Tag

Il provider può aggiungere un Service Tag esterno, tipicamente 0x88A8, conservando il Customer Tag interno 0x8100. Clienti differenti possono riusare gli stessi Customer VLAN Identifier (C-VID).

Trunk CE–PE. Sul collegamento Customer Edge–Provider Edge possono essere consegnate più VLAN cliente. Il tagging effettivo dipende dal contratto e dalla configurazione: singolo tag, doppio tag, subinterfacce o accesso untagged sono scelte di servizio, non proprietà universali di ogni collegamento.

07

Il tipo di servizio cambia il confine

Layer 3 Virtual Private Network (L3VPN) e Layer 2 Virtual Private Network (L2VPN) non trattano allo stesso modo la trama cliente

La distinzione evita un equivoco frequente: il Provider Edge può terminare il collegamento cliente e instradare il datagramma, oppure offrire al cliente una continuità Layer 2 attraverso il backbone.

L3

Layer 3 Virtual Private Network (L3VPN)

Il Provider Edge (PE) termina la trama cliente, esamina il datagramma Internet Protocol (IP) nella Virtual Routing and Forwarding (VRF) e crea il pacchetto labeled e la trama del core. Gli indirizzi Media Access Control (MAC) cliente non attraversano il backbone come identità end-to-end.

L2

Layer 2 Virtual Private Network (L2VPN)

Il servizio trasporta una Protocol Data Unit (PDU) Ethernet o una service instance cliente attraverso uno pseudowire o altra tecnologia L2VPN. L'involucro fisico del link, come preambolo e normalmente Frame Check Sequence (FCS), non coincide necessariamente con ciò che viene trasportato.

Service plane. VLAN, Service VLAN, pseudowire e Virtual Routing and Forwarding rispondono alla domanda “a quale servizio cliente appartiene questo traffico?”. Non sostituiscono il data plane: preparano o aggiungono il contesto con cui le trame e i pacchetti vengono consegnati separatamente.

09

Autoverifica

Domande di orientamento

Formula prima la risposta. Lo scopo è distinguere ambito locale, servizio provider e comportamento dei dispositivi.

1. Se Host B è su una rete IP remota, quale MAC destinazione usa Host A?

Quello del prossimo hop locale, normalmente il gateway, non quello dell'Host B remoto. Il datagramma IP conserva invece l'indirizzo IP della destinazione finale.

2. Uno switch impara osservando il MAC sorgente o quello destinazione?

Impara dal MAC sorgente della trama ricevuta, associandolo alla porta d'ingresso e alla VLAN. Usa il MAC destinazione per decidere l'uscita.

3. Che cosa accade a un unknown unicast?

Lo switch lo replica sulle porte ammesse nella stessa VLAN, eccetto quella d'ingresso. Quando apprende la destinazione, può passare all'inoltro unicast selettivo.

4. Gli indirizzi MAC cambiano attraversando un normale switch?

Normalmente no all'interno dello stesso dominio Layer 2. Possono cambiare tag e FCS per il collegamento d'uscita; un router termina invece la trama e ne costruisce una nuova.

5. Un tag IEEE 802.1Q identifica un nuovo Physical Layer?

No. Aggiunge contesto di bridge e VLAN alla trama. Rame, fibra e backplane sono scelte del Physical Layer IEEE 802.3.

6. Qual è la differenza essenziale fra C-Tag e S-Tag nel Q-in-Q?

Il C-Tag descrive la VLAN cliente; il provider aggiunge un S-Tag esterno per identificare il servizio nella propria rete bridged, conservando il tag cliente interno.

7. Perché una trama Ethernet non è end-to-end attraverso più router?

Perché gli indirizzi MAC, il tag e la FCS hanno significato sul collegamento o dominio Layer 2 corrente. Ogni router decapsula e crea un involucro adatto al next hop successivo.

8. In una L3VPN il PE trasporta intatta la trama cliente nel core?

No. Il PE termina la trama, esamina il datagramma IP nel contesto VRF e costruisce label e trama del core. In una L2VPN, invece, una PDU Ethernet o service instance cliente può essere il contenuto del servizio.

9. EtherType 0x8847 che cosa annuncia?

Che il payload inizia con uno stack di label Multiprotocol Label Switching. Dopo le label si trova il contenuto trasportato, per esempio il datagramma cliente.

Punto di arrivo dell'Unità 2

Ethernet consegna al prossimo hop, non alla fine del viaggio.

La trama rende trasmissibile il payload sul collegamento corrente. Gli switch la inoltrano dentro un dominio Layer 2; i router la terminano e la ricostruiscono. La prossima unità seguirà ciò che resta dentro questi involucri successivi: il datagramma Internet Protocol.
