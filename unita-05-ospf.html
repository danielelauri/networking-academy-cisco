01

Problema originario

Le rotte statiche non descrivono da sole una rete che cambia

Quando aumentano router, collegamenti e percorsi alternativi, configurare manualmente ogni destinazione diventa fragile. Un guasto può rendere obsolete molte scelte: i router devono rilevare la variazione, condividere informazioni attendibili e ricalcolare il cammino.

PRIMA DI OSPF

Configurazione difficile da mantenere

Le rotte statiche sono utili e prevedibili, ma non costruiscono autonomamente una visione completa della topologia e non reagiscono da sole a ogni guasto remoto.

PROBLEMA DISTRIBUITO

Ogni router vede soltanto i propri link

Un’interfaccia locale rivela un collegamento direttamente connesso. Non spiega però quali reti esistano oltre il vicino né quali percorsi alternativi siano disponibili.

RISPOSTA LINK-STATE

Descrivere i collegamenti

I router diffondono Link State Advertisement (LSA), costruiscono una Link State Database (LSDB) coerente nell’area e calcolano localmente l’albero dei cammini più brevi.

Open Shortest Path First (OSPF) non trasporta i dati del cliente.
È un protocollo del control plane: prepara raggiungibilità e next hop che, dopo la selezione nella Routing Information Base (RIB), potranno alimentare la Forwarding Information Base (FIB).

Questa è una classificazione funzionale, non la posizione nella pila di incapsulamento. Border Gateway Protocol controlla raggiungibilità di livello 3 ma scambia i messaggi mediante Transmission Control Protocol; OSPFv2, invece, è trasportato direttamente da Internet Protocol.

02

Ruolo e incapsulamento

Open Shortest Path First (OSPF) è un Interior Gateway Protocol (IGP) link-state

Open Shortest Path First version 2 (OSPFv2) opera all’interno di un singolo Autonomous System (AS) Internet Protocol version 4 (IPv4). Ogni router mantiene una Link State Database (LSDB) per area, deriva un albero Shortest Path First (SPF) con se stesso come radice e propone rotte alla tabella di routing.

AMBITO

Intra-domain

OSPF costruisce raggiungibilità interna a un dominio amministrativo. Non applica le policy inter-domain tipiche di Border Gateway Protocol.

MODELLO

Link-state

Descrive router, link, reti multiaccess e raggiungibilità entro il perimetro previsto dal tipo di Link State Advertisement.

RISULTATO

Percorsi calcolati localmente

I router con la stessa Link State Database e gli stessi costi calcolano una visione coerente, ciascuno dalla propria prospettiva.

IPv4campo Protocol = 89 · TTL normalmente 1 sui collegamenti ordinari

Esempio IOS: attivare OSPF sul collegamento PE-A–P1sintassi illustrativa, piano di indirizzamento del corso
router ospf 1
 router-id 192.0.2.1

Legenda: 1 = process ID, locale e obbligatorio; 0.0.0.3 = wildcard mask del /30 203.0.113.0/30; area 0 = Area ID del backbone; 0.0.0.0 = wildcard che seleziona un solo indirizzo, qui la loopback di PE-A.

Tre numeri da non confondere. In router ospf 10 il valore è il process ID; in network … area 10 è l’Area ID; in router eigrp 10 è il numero di sistema autonomo di un altro protocollo. Il comando network non annuncia una rete: individua le interfacce i cui indirizzi ricadono nell’intervallo indicato e le associa all’area. Per inserire nell’area 0 la rete 10.2.3.0/24 serve network 10.2.3.0 0.0.0.255 area 0 dentro router ospf. La wildcard mask è l’inverso della maschera: un bit a 0 deve coincidere, un bit a 1 è indifferente.

Hello verso indirizzi multicast. Sulle reti multiaccess come Ethernet i pacchetti Open Shortest Path First (OSPF) usano due indirizzi multicast Internet Protocol version 4 (IPv4) con TTL 1: 224.0.0.5 (AllSPFRouters, tutti i router OSPF) e 224.0.0.6 (AllDRouters, Designated Router e Backup Designated Router). Un collegamento che non inoltra il multicast impedisce la scoperta dei vicini; sui collegamenti non-broadcast si configurano invece vicini unicast.

04

Dal vicino alla sincronizzazione

Neighbor e adiacenza non sono sempre sinonimi

Ricevere Hello compatibili crea una relazione di vicinato. L’adiacenza completa richiede anche la sincronizzazione delle informazioni link-state. Sui collegamenti point-to-point i vicini tendono a diventare completamente adiacenti; su Ethernet multiaccess il Designated Router (DR) e il Backup Designated Router (BDR) riducono il numero di adiacenze necessarie.

Macchina degli stati del neighborseleziona uno stato
FULL: Link State Database sincronizzata.I router sono completamente adiacenti. Se le rotte attese mancano ancora, la diagnosi deve proseguire su LSDB, calcolo SPF, selezione nella RIB, filtri o installazione nella FIB.
POINT-TO-POINT

Full con il vicino

Non serve l’elezione di Designated Router e Backup Designated Router; i router cercano normalmente di sincronizzare completamente le proprie LSDB.

BROADCAST MULTIACCESS

DR e BDR riducono le adiacenze

I Designated Router Other diventano FULL con DR e BDR, ma possono restare correttamente 2-WAY fra loro.

2-WAY NON È SEMPRE UN GUASTO

Interpretare il network type

Prima di correggere uno stato 2-WAY occorre capire il ruolo locale e remoto sul segmento.

FULL descrive la sincronizzazione dell’adiacenza, non garantisce da solo la presenza di ogni rotta attesa. Una rotta può mancare perché la LSA non esiste, il prefisso non è annunciato, il calcolo non la seleziona oppure un’altra sorgente vince nella Routing Information Base.

05

Flooding e database

Le Link State Advertisement (LSA) descrivono la topologia; la Link State Database (LSDB) ne conserva la visione

Una Link State Advertisement è un oggetto informativo trasportato dentro un Link State Update. Il flooding distribuisce le LSA lungo le adiacenze ammissibili; numeri di sequenza, età e acknowledgment aiutano a riconoscere le versioni più recenti e a sincronizzare il database.

06

Dalla mappa ai percorsi

Shortest Path First (SPF) costruisce un albero con il router locale come radice

La Link State Database (LSDB) è una mappa, non ancora una tabella di forwarding. L’algoritmo Shortest Path First (SPF) usa i costi Open Shortest Path First (OSPF) per determinare i cammini verso router e reti; il costo di un percorso è la somma dei costi delle interfacce di uscita attraversate secondo il modello OSPF.

07

Scalabilità gerarchica

Le aree limitano il dettaglio e Area 0 collega il dominio

Ogni area possiede una propria Link State Database (LSDB). Il backbone Open Shortest Path First (OSPF), Area Identifier (Area ID) 0.0.0.0, distribuisce la raggiungibilità fra aree; gli Area Border Router (ABR) partecipano al backbone e riassumono la topologia esterna a un’area in informazioni inter-area.

Legenda: OSPF = Open Shortest Path First; LSDB = Link State Database; ABR = Area Border Router.

INTRA-AREA

Dettaglio della propria area

Router-LSA e Network-LSA descrivono la topologia usata per calcolare i percorsi interni all’area.

INTER-AREA

Raggiungibilità attraverso il backbone

Gli Area Border Router annunciano nelle aree informazioni distillate sulle destinazioni esterne all’area.

BENEFICIO

Minore dominio di flooding e calcolo

Le variazioni interne a un’area non distribuiscono ovunque lo stesso dettaglio topologico.

Le aree non sono Virtual Routing and Forwarding. Suddividono gerarchicamente un unico dominio OSPF; non creano automaticamente tabelle cliente separate e non costituiscono una Layer 3 Virtual Private Network.

Diagnosi operativa

Lo stato del neighbor determina il prossimo controllo

Una checklist efficace parte dal livello fisico e dai parametri dell’interfaccia, osserva poi lo stato dell’adiacenza e soltanto dopo verifica database e rotte. Ogni controllo va eseguito su entrambi i lati del collegamento.

Checklist completa, nell’ordine corretto

  1. Verificare stato e indirizzamento con show ip interface brief su entrambi i router.
  2. Leggere i parametri effettivi con show ip ospf interface.
  3. Controllare presenza, Router ID, ruolo e stato mediante show ip ospf neighbor.
  4. Confrontare Area ID, Hello Timer, Dead Timer e opzioni stub.
  5. Confrontare autenticazione, metodo e chiavi.
  6. Verificare la Maximum Transmission Unit, soprattutto se lo stato resta EXSTART o EXCHANGE.
  7. Verificare che i Router ID siano univoci.
  8. Controllare passive-interface e OSPF network type.
  9. Verificare Access Control List e firewall: OSPFv2 usa direttamente IPv4 Protocol 89, non una porta Transmission Control Protocol o User Datagram Protocol.
  10. Con adiacenza FULL, passare a show ip ospf database, show ip route ospf e show logging.
PROBLEMA DI VICINATO

Hello assente o incompatibile

La diagnosi resta su interfaccia, abilitazione OSPF, parametri comuni, autenticazione, rete multiaccess e filtri.

PROBLEMA DI SINCRONIZZAZIONE

EXSTART, EXCHANGE o LOADING

I router si sono visti, ma lo scambio non termina: Maximum Transmission Unit, negoziazione Database Description, sequenze o LSA richieste meritano attenzione.

PROBLEMA DI ROTTA

FULL ma destinazione assente

Il vicinato è completo: verificare LSA nella LSDB, annuncio del prefisso, area, costo, calcolo SPF, distanza amministrativa e installazione nella RIB/FIB.

Non iniziare modificando il process ID OSPF. È locale al router e non deve coincidere con quello del vicino. Cambiare parametri senza partire dallo stato osservato può interrompere un’adiacenza corretta e nascondere la causa reale.

10

Collocazione e limiti

Open Shortest Path First (OSPF) conosce l’interno; non sostituisce tutti gli altri piani

Open Shortest Path First (OSPF) risolve il problema della raggiungibilità dinamica intra-domain. Non offre affidabilità applicativa, non separa clienti e non sostituisce i protocolli orientati alle policy fra Autonomous System (AS).

OSPF FA

Topologia e percorsi interni

Forma adiacenze, distribuisce LSA, mantiene LSDB per area, calcola cammini e propone rotte.

OSPF NON FA

Trasporto dei dati

I datagrammi cliente sono inoltrati dal data plane mediante la FIB; OSPF prepara le informazioni.

OSPF NON FA

Separazione dei clienti

Aree e processi non equivalgono automaticamente a Virtual Routing and Forwarding o Virtual Private Network.

OSPF NON FA

Policy inter-domain

Border Gateway Protocol usa attributi e policy per la raggiungibilità fra Autonomous System.

Cenno a Intermediate System to Intermediate System

Intermediate System to Intermediate System è un altro Interior Gateway Protocol link-state, molto diffuso nei backbone dei Service Provider. Condivide con OSPF l’idea di una base topologica e di un calcolo Shortest Path First, ma usa terminologia, incapsulamento e organizzazione gerarchica differenti. In questa unità serve come riferimento comparativo, non come deviazione dal percorso principale.

12

Autoverifica

Domande di orientamento

Rispondi prima di aprire ogni scheda. Le domande verificano relazioni e sequenze, non soltanto definizioni.

1. Perché due router della stessa area dovrebbero avere Link State Database coerenti?

Perché il calcolo SPF è locale: una base topologica coerente permette di derivare percorsi compatibili. Gli alberi non sono identici, poiché ciascun router usa se stesso come radice.

2. Un pacchetto OSPFv2 usa una porta UDP o TCP?

No. È trasportato direttamente da IPv4 con valore Protocol 89. Il numero di protocollo IP non è una porta.

3. Qual è la differenza fra Link State Update e Link State Advertisement?

Link State Update è un tipo di pacchetto OSPF. Il payload può contenere una o più Link State Advertisement.

4. Perché due DROTHER possono rimanere correttamente 2-WAY su Ethernet?

Perché sulle reti broadcast multiaccess diventano normalmente FULL con DR e BDR; non occorre una piena adiacenza fra ogni coppia di DROTHER.

5. FULL garantisce che tutte le rotte OSPF attese siano nella RIB?

No. FULL indica sincronizzazione dell'adiacenza. Occorre ancora verificare LSA, calcolo SPF, annuncio del prefisso e selezione nella RIB.

6. Che cosa suggerisce uno stato persistente EXSTART o EXCHANGE?

La scoperta bidirezionale è avvenuta, ma la sincronizzazione Database Description non termina. MTU, negoziazione, Router ID duplicati o sequenze inattese sono controlli pertinenti.

7. Il process ID OSPF Cisco deve coincidere fra vicini?

No. È localmente significativo. Area ID e altri parametri dell'interfaccia devono invece essere compatibili.

8. “Percorso più breve” significa sempre minor numero di router?

No. SPF minimizza il costo OSPF totale; il costo non coincide necessariamente con hop count o latenza reale.

9. In quale ordine essenziale OSPF arriva al forwarding?

Adiacenze → LSA/LSDB → SPF → rotte candidate → RIB → FIB e adiacenze Layer 2.

10. Le aree OSPF separano automaticamente i clienti come una VRF?

No. Le aree suddividono gerarchicamente il dominio link-state; una VRF crea un contesto separato di routing e forwarding.

11. Il process ID OSPF su Cisco IOS è facoltativo?

No. È obbligatorio in router ospf <process-id> ed è localmente significativo: identifica un’istanza di OSPF, con la propria LSDB, sul solo router locale. Non deve coincidere con quello dei vicini.

12. Quali due comandi inseriscono la rete 10.2.3.0/24 nell’area 0?

router ospf <process-id> e, al suo interno, network 10.2.3.0 0.0.0.255 area 0. Attenzione ai numeri: area 10 indica un’altra area, router eigrp un altro protocollo.

13. OSPF usa il multicast IP sulle reti multiaccess come Ethernet?

Sì. Gli Hello e gli aggiornamenti usano 224.0.0.5 per tutti i router OSPF e 224.0.0.6 per DR e BDR, sempre con TTL 1.

14. Due vicini restano in EXSTART o EXCHANGE: tra multicast interrotto, interfaccia passiva, ACL sugli Hello e MTU diversa, quale causa è coerente con lo stato?

La MTU diversa. Le altre tre cause impediscono già lo scambio degli Hello: il vicino non arriverebbe nemmeno a 2-WAY. EXSTART ed EXCHANGE indicano che gli Hello funzionano e che si blocca lo scambio dei Database Description.
